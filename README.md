**Real-time. Automated. Intelligent.**

A custom Security Orchestration, Automation and Response (SOAR) engine built for Enterprise Cloud / MSSP environments. The engine ingests raw SIEM alerts, automatically enriches them with live threat intelligence, maps them to the MITRE ATT&CK framework, and executes predefined defensive playbooks — achieving full alert-to-containment in **under 5 seconds**.

---

## Problem Statement

SOC analysts are overwhelmed by the volume of alerts generated by SIEM systems. Manually triaging alerts, querying threat intelligence databases, and logging into firewalls to block malicious IPs takes too long — allowing attackers to move laterally across cloud environments. This engine eliminates that bottleneck through full automation, with human-in-the-loop controls for the highest-impact actions.

## Key Features

### Alert Ingestion & Normalisation
- FastAPI webhook endpoint accepts raw SIEM alerts in any format
- Normalises inconsistent timestamp formats, IP field names, and severity labels
- Validates against a strict Pydantic schema before any enrichment runs

### Automated Threat Enrichment
- **AbuseIPDB** — IP reputation score (0–100 confidence)
- **VirusTotal** — multi-vendor threat analysis (malicious/suspicious/harmless counts)
- **IP-API** — geolocation, ISP, organisation, city, timezone
- All three sources queried; graceful fallback if any API is unavailable

### MITRE ATT&CK Mapping
Every alert is automatically tagged with the relevant ATT&CK technique:

| Alert Type | Technique ID | Technique Name | Tactic |
|---|---|---|---|
| Brute Force | T1110 | Brute Force | Credential Access |
| Malware | T1059 | Command and Scripting Interpreter | Execution |
| Phishing | T1566 | Phishing | Initial Access |
| Ransomware | T1486 | Data Encrypted for Impact | Impact |
| Port Scan | T1046 | Network Service Discovery | Discovery |

Tags are clickable links in the dashboard, pointing directly to the MITRE ATT&CK knowledge base.

### Risk-Based Playbook Execution
A graduated response system — not every alert gets the same action:

| Risk Score | Action |
|---|---|
| 0 – 39 | Log event only |
| 40 – 69 | Create case for analyst review |
| 70 – 89 | Auto-block IP / create case |
| 90 – 100 | Immediate containment + approval gate for host isolation |

### Containment Actions
- **Firewall Simulator** — blocks malicious IPs; persists to `blocked_ips` table; queryable at `GET /blocked_ips`
- **Host Isolator (EDR)** — isolates compromised hosts; persists to `isolated_hosts` table; only executes after senior analyst approval

### RBAC + JWT Authentication
Three roles enforced at both the API and frontend levels:

| Role | Permissions |
|---|---|
| `soc_analyst` | View alerts, dashboard, cases, timeline, threat intel |
| `security_engineer` | All above + automation settings, admin panel |
| `senior_analyst` | All above + **approve / reject high-impact containment actions** |

JWT tokens signed with HS256, 8-hour expiry.

### Senior Analyst Approval Workflow
Critical malware containment (host isolation) does not auto-execute. Instead:
1. Engine flags the alert as `"Pending Approval"` and creates a record in `pending_approvals`
2. Dashboard shows the pending action with Approve / Reject buttons — active only for `senior_analyst`
3. On approval, `HostIsolator` executes, alert status updates to `Resolved`, action is logged

This preserves the sub-5-second decision time (the core KPI) while adding a human checkpoint for the highest-blast-radius action.

### Performance
- **MTTR target**: < 5 seconds (alert ingestion → enrichment → playbook → containment decision)
- Each alert response includes `mttr_seconds` and `within_sla: true/false`
- Measured with `time.perf_counter()` across the full pipeline

## Setup & Installation

### Prerequisites
- Python 3.10+
- Node.js 18+ (for the React frontend)
- AbuseIPDB API key — [abuseipdb.com](https://www.abuseipdb.com)
- VirusTotal API key — [virustotal.com](https://www.virustotal.com)

### 1. Clone the repo

```bash
git clone https://github.com/vrushti0908/SOAR-Incident-Containment-Engine-.git
cd SOAR-Incident-Containment-Engine-
```

### 2. Set up environment variables

Create a `.env` file in the repo root:

```env
ABUSEIPDB_API_KEY=your_abuseipdb_key_here
VIRUSTOTAL_API_KEY=your_virustotal_key_here
JWT_SECRET_KEY=change-this-to-a-random-string-in-production
```

### 3. Install Python dependencies

```bash
pip install -r requirements.txt
```

### 4. Initialise the database and seed demo users

```bash
python seed_user.py
```

Creates `soar.db` with three demo users:

| Username | Password | Role |
|---|---|---|
| `analyst1` | `analyst123` | `soc_analyst` |
| `engineer1` | `engineer123` | `security_engineer` |
| `senior1` | `senior123` | `senior_analyst` |

### 5. Start the FastAPI backend

```bash
python -m uvicorn app.main:app --reload
```

- API: `http://127.0.0.1:8000`
- Interactive docs: `http://127.0.0.1:8000/docs`

### 6. Start the React frontend

```bash
cd frontend
npm install
npm run dev
```

Dashboard: `http://localhost:5173`

## API Reference

### Alerts

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/alerts` | Ingest, enrich, and execute playbook on a new alert |
| `GET` | `/alerts` | Retrieve all stored alerts |

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/auth/login` | Log in and receive a JWT |
| `GET` | `/approvals` | List all approvals (any authenticated role) |
| `POST` | `/approvals/{id}/approve` | Approve a high-impact action (senior_analyst only) |

## SOC Tier Mapping

This engine targets **Tier 1 SOC automation** with **Tier 2 decision support**:

- **T1 automated**: alert triage, threat enrichment, risk scoring, routine containment (IP blocking, case creation, logging)
- **T2 boundary preserved**: host isolation on critical alerts requires explicit `senior_analyst` sign-off — mirroring how real enterprise SOAR platforms handle high-blast-radius actions

## Disclaimer

This project uses simulated firewall and EDR components for the containment layer. All blocking and isolation actions are recorded in a local SQLite database and do not affect real network infrastructure. AbuseIPDB and VirusTotal API keys are required for live threat enrichment — without them, risk scores default to 0.
